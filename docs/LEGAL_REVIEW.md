[来源清单](UPSTREAM.md) 记录了 Dobby 预编译静态库、xdl 源码和构建依赖等待核实对象。项目名、目录名或网上同名项目的许可证，不能单独证明本仓库所含字节的版本和许可。此次未确认单独的组件许可/通知文件；这项观察不等于证明原作者从未提供，也不等于认定有人删除了通知。

应先逐项核对上游提交、版权声明、原始分发材料和本地修改，再形成与实际源码和 APK 对应的组件清单。条件性义务包括：

- 若某部分适用 Apache-2.0：核对第 4 节要求，包括提供许可证副本、对修改文件作显著修改说明、保留适用的版权和归属声明。上游若随作品提供 NOTICE，应按相应条款保留适用通知；不能把所有 Apache 项目一律描述为必须新建 NOTICE。
- 若某部分适用 GPL-3.0：结合第 1、4、5、6 节及具体分发方式，评估修改源码、整体作品范围及目标代码的对应源码义务。公开一个源码仓库本身不足以证明每个已分发 APK 的义务均已满足；构建脚本及适用的其他材料也需核对。
- Apache-2.0 第 6 节并不普遍授予使用上游商号、商标、服务标志或产品名称的权利，许可中的有限例外需按其原文理解。

## 2. WhatsApp 服务条款与第三方应用权限

核对的官方条款对未获允许的使用、复制、修改、代码提取、逆向工程及部分自动化行为设有限制，也规定暂停或终止账户的措施。实际约束应以用户所在地、服务主体和适用版本为准；本次未完成地区版本逐一核对。

本项目包含第三方应用导入、虚拟化和 hook，住宅代理及模拟定位又会改变运行环境。这些事实需要与适用条款逐项评估，不能仅凭“用户已安装 APK”或“账号属于本人”推导出复制、修改或再分发授权。

违反平台合同与违反法律是不同问题；不能据此认定所有分身使用都违法，也不能承诺账号安全、不会封禁或已获平台认可。代理和模拟定位本身是否允许，应结合用途、第三方约定和适用法域判断。本次没有调查用户的具体业务用途。

管理器目前没有实现验证码自动读取、统一消息中心或批量消息发送功能。今后增加这些功能需重新评估，不能套用本次结论。

## 3. 名称、图标与品牌关联

README 标题已改为“多开空间”，并说明其第三方衍生项目性质；WhatsApp 名称用于说明当前适配对象。这个说明有助于避免暗示官方关系，但不能单独证明所有名称使用均获许可。

[MainActivity.java](../manager/src/main/java/com/yshut/whatsappspaces/MainActivity.java) 仍从已安装应用读取图标，用于空间卡片；pin 方法将原图标绘制后叠加空间编号生成快捷方式。Meta 的 WhatsApp 品牌指南对暗示合作/认可、组合名称或图标、改变品牌资源等设有限制。实际图标行为应单独核对，不能因图标来自用户手机便自动认定没有风险。

本次只修改文档，未改图标或快捷方式代码。后续可评估以自有通用图标表示空间，并保留必要的文字兼容性说明；最终方案仍需结合适用的品牌规则和法律判断。

## 4. 隐私、安全与宣传表述

[数据与权限说明](PRIVACY.md) 列出了已观察到的接收方、保存形式及关闭功能后的行为。主要缺口是运营主体与联系方式、具体数据处理目的、接收方评估、保留和删除流程，以及与真实运行权限一致的告知与必要授权。

本地 AES-GCM 加密只描述代理配置的保存形式，不能扩大成所有数据和传输均安全；不同数据目录不能扩大成系统用户级隔离；移除一个远程日志实现不能扩大成全应用零外传。README 已明确这些限制。

不同法域对个人信息、位置、消息数据及网络服务可能适用不同要求。本次未对特定法域作合规判定，也未审计 VPN/代理供应商、IP 查询服务或分身内应用的全部数据流。
